# Six-minute recording script

Do not record the final success walkthrough until genuine live-model cases pass without fallback.
An outage demonstration may be recorded separately and must be labelled as such.

| Time | Screen / action | Narration |
|---|---|---|
| 0:00–0:35 | Cover and track name | Ryde Tribunal, Digital Native track. Fair ride disputes, resolved through evidence and policy. Explain the reviewer and the evidence problem. |
| 0:35–1:00 | Architecture | Introduce two advocates, Judge, read-only evidence tools, policy and validation gates. |
| 1:00–2:10 | Route case | File a route complaint on a fixed-price trip. Open both arguments, evidence and official route policy. Explain why a longer route alone is not an invented refund entitlement. |
| 2:10–3:25 | No-show case | Show an invalid charge in the free window. Trace the matching and cancellation events. Show a S$6.61 voucher recommendation, supported decisive facts and provider identity. |
| 3:25–4:15 | Uncertain case | Show contradictory or missing decisive evidence. Open the review summary and explain the gap. |
| 4:15–5:00 | Reviewer decision | Override with a reason; show separate model proposal and human ruling, then export both party explanations. |
| 5:00–5:35 | Dataset and evaluation | Show synthetic corpus counts, human review gate and independently held-out benchmark results. State measured outcomes and limitations accurately. |
| 5:35–6:00 | Tool usage and reflection | Show genuine CodeBuddy/WorkBuddy evidence and one concrete improvement. Explain the build approach and next steps. |

Recording checklist: readable text; no credentials or company data; both core categories; actual
agent activity; provider labels; no edited illusion of model success; six-minute duration; reviewed
captions and audio; final playback check. The final recording is pending the live-model gate and
external tool evidence.
