# Company CSV import bundle, format v1

The importer accepts a ZIP archive containing UTF-8 CSV files at the archive root. It imports
company trip/profile/evidence records into the local queryable ride database. A dispute is filed
separately against an imported trip; this archive must not contain a dispute ticket.

Required members:

- `manifest.json`: `{"format_version":"1","source_system":"company-export-name"}`. `source_system`
  is a stable namespace for source IDs; it is import metadata, not an internal ID.
- `users.csv`: `company_user_id,role,name`
- `profiles.csv`: `company_user_id,account_age_days,total_trips,avg_rating,dispute_history_total,dispute_history_upheld,dispute_history_rejected,dispute_history_upheld_against,fraud_flags,fraud_flag_details,payment_method,vehicle`
- `trips.csv`: `company_trip_id,company_rider_id,company_driver_id,pickup_location_name,pickup_lat,pickup_lng,dropoff_location_name,dropoff_lat,dropoff_lng,scheduled_time,driver_arrival_time,driver_wait_start,cancellation_time,cancellation_fee,cancellation_reason`
- `gps_telemetry.csv`: `company_trip_id,sequence_no,timestamp,lat,lng,speed_kmh,status`
- `chat_logs.csv`: `company_trip_id,sequence_no,timestamp,sender,type,content`
- `app_events.csv`: `company_trip_id,sequence_no,timestamp,event_type,details`

Optional member:

- `evidence_metadata.csv`: `record_type,company_trip_id,company_user_id,sequence_no,verification_status,verified_by,verified_at,evidence_source`. `record_type` is one of `trip`, `route`, `fare`, `profile`, `gps_telemetry`, `chat_log`, or `app_event`. Trip/route/fare metadata keys use `company_trip_id`; profile metadata uses `company_user_id`; GPS/chat/app-event metadata uses `company_trip_id` plus `sequence_no`. Unused key columns must be blank. Every key must match a record in a required CSV.
- `ratings.csv`: `company_trip_id,company_rated_user_id,rating_from_role,rating,rated_at`. If present, `trips.csv` must also include `ride_status`; completed trips have exactly two participant ratings, and cancelled trips have none. Every user profile must have at least one received rating and `avg_rating` must match the average received rating rounded to two decimals.

The following `trips.csv` columns are optional for existing company exports and may be supplied for generated test datasets: `ride_status,service_tier,quoted_distance_meters,quoted_duration_seconds,quoted_fare_cents,fare_breakdown_json,pricing_structure`. `fare_breakdown_json` contains the queryable `ride_fare_breakdowns` fields (in cents), and `pricing_structure` is preserved as trip provenance. The manifest may set `"synthetic": true` for a synthetic dataset bundle; otherwise imported records are marked as non-synthetic company records.

Cancellation policy is not imported. Adjudication uses the existing project policy file.

The `sequence_no` column may be omitted or left blank in GPS, chat, and app-event CSVs. The importer stores a
zero-based, per-trip CSV row order in the database `sequence_no` column so reads reproduce the source
array order. A supplied source sequence is preserved in `provenance.source_sequence_no`, and
`provenance.sequence_no_origin` identifies the stored ordering as `csv_row_order`. For row-level
`evidence_metadata.csv`, `sequence_no` means the zero-based row order within that trip and CSV type,
even when the source CSV sequence cell is blank. The chat `type` value is preserved as supplied,
including `message`, `system`, and `call`.

Blank values are preserved as blank and are not replaced with fabricated trip measurements. Imported
evidence without supplied verification metadata is treated as unverified. Row links use the
`company_*_id` source references; internal database IDs are generated by the application. The
importer validates all CSV headers and row references before writing. Import operations append and
must not reseed or truncate existing data.

After a successful import, the operator receives a separate CSV mapping with only
`source_system,record_type,company_source_id,internal_id` columns for every user and trip in the
bundle, including IDs that were already present. Existing company IDs are matched globally by
record type, even if an earlier import used a different `source_system`; those rows are skipped
without updating stored content and their existing internal IDs are returned. New trip rows can
link to a skipped user through that user's existing internal ID. The CLI reports inserted counts
and skipped company IDs. No names, profile details, chat text, or other imported content is written
to the mapping output.

Validate a bundle without writing data:

```bash
cd database
uv run python -m importer validate /path/to/company-export.zip
```

Import and save the ID mapping to a new file (the file must not already exist):

```bash
cd database
uv run python -m importer import /path/to/company-export.zip --mapping-out /path/to/company-id-mapping.csv
```

Without `--mapping-out`, the mapping CSV is printed to standard output. Set `DATABASE_URL` when
the local default `postgresql:///ryde_tribunal` is not the intended database.

No populated company dataset or copy of the supplied example is stored in Git. Examples and tests
must use fake or empty values only.
